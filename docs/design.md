# liteOS 设计文档

> 一切皆运动。基座只管运动控制，无状态，可被任意大脑骑乘。

**语言 / Languages:** **中文** · [English](design.en.md)

---

## 0. 定位

liteOS 不是"一个操作系统"，而是一个**基座**：一个只管运动控制、无状态、可被任意上层大脑骑乘的底座。

| 层 | 角色 | 特征 |
|---|---|---|
| **上层大脑** | 意图、策略、智能 | 可热插拔，随时替换 |
| **基座** | 只做运动控制 | 唯一不变、无状态（**"可信"是目标，尚未由隔离保证**） |
| **物件** | 物理世界 | 即插即用，受基座控制运动 |

---

## 1. 本体论：一切皆运动

1. 万事万物都是运动
2. 没有运动，物件不存在
3. **静止是一种相对的运动**

### 第 3 条是整个设计的支点

它的推论：

- 「静止」不是运动的一个取值，而是**一次比较的结果**
- 比较需要**参照系**，参照系是**信息**
- 基座不保存信息 ⇒ **判定「静止 / 运动」不在基座职责内**

**因此：判定归大脑，施加归基座。**

---

## 2. 唯一原语：施加运动

由第 1 条推到底：

> **基座只有一个指令：施加运动。**
> 没有「停止」这个指令 —— 「静止」就是「以参照系的运动为自身的运动」。

| 意图 | 基座实际执行 |
|---|---|
| 让它运动 | `施加运动(物件, 运动, 参照系, 时长)` |
| 让它静止 | `施加运动(物件, 与参照系同步, 时长)` |

**两行是同一个操作，只是参照系不同。**

基座**永远不区分**「运动」与「静止」，因此基座里没有 `MOVING` / `STILL` 这两个枚举值，一个都不需要。

> 状态机消失了，只剩一个函数。

---

## 3. 基座：无状态的运动控制函数

```
基座 = f(自描述的运动控制事件) → 对物件施加运动
```

### 3.1 无状态，因此事件必须自描述

基座不保存信息 ⇒ 没有可用的参照系 ⇒ 每条事件必须自带上下文。

> **运动控制事件是自描述的**：自带目标、运动内容、参照系、时长。

这是无状态基座能够成立的**全部秘密**：它不需要记忆，因为**每个事件自带一个世界**。

反过来看也成立：**基座之所以能无状态，恰恰因为「静止」是相对的** —— 参照系可以从事件里来，不必从基座里来。

### 3.1.1 `duration_ns` 的语义：新鲜度窗口（拾取器模型的修正）

`duration_ns` 曾经的意思是「这条事件的有效时长」。这个说法有两个漏洞：

1. **它无法被拒绝。** 既然只是「多久之后失效」，那么任何迟到的命令都照样执行 ——
   一个在地下室里放了两小时的抓取命令，放到台面上时仍然有效。
2. **它在实现里是死字段。** `duration_ns` 从未参与任何校验、拒绝或替换，
   连带 `MOTION_E_DEADLINE` 成为不可达路径。一个永远不生效的状态码不是安全网，
   是安全感的错觉。

现在它被冻结为**命令的新鲜度窗口**：事件自带发出时刻，最迟必须在
`issued_at_ns + duration_ns` 之前被接受。

| 模型 | 语义 | 窗口闭合之后 |
|---|---|---|
| 遥控器 / remote control | 持续推，松手即回落 | 物件回到默认状态 |
| 拾取器 / pick-and-place | 把物件放到一条轨道上 | 物件继续沿轨道运动 |
| **新鲜度窗口 / freshness（现行）** | **只在窗口内可被接受** | **迟到的命令被拒绝，不执行；已接受的轨道照旧走完** |

拾取器模型的「自持」被**完整保留**：接受之后不需要续喂，物件自己沿轨道走。
改的只是「接受」这一步有了时间闸门。

| 设计决定 | 新鲜度窗口如何满足 |
|---|---|
| 基座无状态 | 判定只需要「现在」与事件里的两个数，基座不存时间，判定发生在物件层 |
| 物件自带运动能力 | 窗口闭合不影响已接受的轨道 |
| 大脑可热插拔 | 旧大脑下台后残留的迟到命令，会被提交时刻直接拒绝 |
| 静止是相对的 | 不变：「静止」仍是 `motion = 0` 的事件 |

> **事件有一条寿命；寿命之内才生效。生效之后，物件仍在运动。**

判定的边界，逐条写死：

| 情形 | 结果 |
|---|---|
| `duration_ns == 0` | `MOTION_E_INVAL`（零长度窗口永远无效） |
| `issued_at_ns + duration_ns` 回绕 | `MOTION_E_INVAL`（否则会伪造一个永不过期的窗口） |
| `issued_at_ns > 现在` | `MOTION_E_INVAL`（未来事件，时间来源异常） |
| `现在 == deadline` | 接受（窗口闭合的那一刻仍在窗口内） |
| `现在 > deadline` | `MOTION_E_DEADLINE`（拒绝，绝不执行） |

**「现在」是提交时刻，由调用者显式传入**：

```c
motion_status_t base_apply(u64 now_ns, const motion_event_t *ev);
motion_status_t object_submit(wire_t w, u64 now_ns, const motion_event_t *ev);
```

基座不计时，所以期限判定只能在物件层做 —— 这不是妥协，而是无状态设计的
直接推论。但**判定所依据的「现在」必须是这条命令到达入口的那一刻**，不能
借用执行层上一次排播的节拍：`object_run()` 两次调用之间提交的命令，若拿
旧节拍当「现在」，一个早该过期的命令会被无限期接受，而刚发出的命令又可能
被判成「发出于未来」。基座不保存这个时刻，物件也不缓存它 —— 它只是本次
调用的一个参数。

### 3.1.2 运动控制事件的形状

```c
/* 设计示意 */
#define MOTION_DOF_MAX 6

typedef struct {
    u64 wire;                    /* 目标：接线句柄；0 无效 */
    u64 frame;                   /* 参照系：另一条接线；0 = 世界系 */
    u64 issued_at_ns;            /* 发出时刻（调用者时钟） */
    u64 duration_ns;             /* 新鲜度窗口长度；0 无效 */
    u8  dof;                     /* 有效分量数，≤ 6 */
    s64 motion[MOTION_DOF_MAX];  /* 相对 frame 的速度，Q32.32 */
} motion_event_t;
```

六个字段对应唯一原语的参数，一个不多一个不少。

**关键：`motion` 是「相对 frame 的运动」。**

于是「静止」不需要单独指令：

| 想要的 | 事件 |
|---|---|
| 绝对静止 | `motion = 0, frame = 世界` |
| 随物件 X 一起动（相对静止） | `motion = 0, frame = X 的接线` |
| 以速度 v 运动 | `motion = v, frame = 世界` |

**静止 = `motion` 取 0。** 这就是「静止是一种相对的运动」在代码里的确切落点。

三条纪律：

1. **没有 opaque 载荷。** 事件里不允许夹带任何非运动数据 —— 「其他一切信息」必须走物件与大脑的直连通道，不得借道基座。这是纪律，不是疏漏。
2. **定点而非浮点。** 基座不碰浮点，避免 FPU 状态保存，也保证 WCET 可静态分析。
3. **参照系就是另一条接线。** 基座因此无需保存任何参照系定义：`frame` 只是一个接线句柄，基座现场校验它当前是否有效。

> 本节只讲「发给物件」的一个方向。**双向的完整契约**（含物件 → 基座的到达 / 离开）见 §3.6。

### 3.2 无状态的边界：接线 vs 信息

| | **接线** | **信息** |
|---|---|---|
| 是什么 | 哪个物件挂在哪个口 | 世界的内容 |
| 例子 | 端口 → 物件的通道 | 位置、速度、意图、图像 |
| 基座持有 | **是** | **否** |
| 类比 | 交换机知道哪条线接到哪个号码 | 交换机不知道你们在聊什么 |

> **接线是执行的必要条件；信息是世界的内容。**
> 基座可以持有前者，绝不持有后者。

### 3.3 基座有什么

```
├── 接线        物件与端口的对应（瞬态管线）
├── 施加运动    唯一原语
├── 到达 / 离开  接线的变更（接线唯一的来源是「到达」事件）
├── 执行瞬态    事件存续期间的计时等执行状态（非世界信息）
└── 隔离        物件之间、大脑与物件之间的边界
```

### 3.4 基座没有什么

```
世界状态         物件状态表        查询接口
静止/运动判定     参照系与上下文     控制律与策略
日志             文件系统          网络栈
驱动模型         用户管理          图形
```

### 3.5 基座是运动控制的唯一通路

所有运动控制必须经过基座。这使基座成为世界运动的唯一执行者，**同时不需要它保存任何世界信息**。

### 3.6 双向接口契约：各传什么

集中写清跨越基座边界的全部数据。**只有三条路，没有第四条。**

| 方向 | 接口 | 内容 | 是状态吗 |
|---|---|---|---|
| 物件 → 基座 | `base_arrive()` | 无（到达本身） | 否，到达通知 |
| 物件 → 基座 | `base_depart(wire_t)` | 句柄 | 否，离开通知 |
| 大脑 → 基座 | `base_apply(motion_event_t)` | 见下 | 否，命令 |
| 基座 → 物件 | `object_submit(wire, motion_event_t)` | 同一个结构 | 否，命令 |

**没有「查询」这一行。** 基座从不问物件任何事：没有 `get_state()`、没有 `poll()`、没有心跳。

#### 发给物件的全部内容

```c
typedef struct {
        wire_t          wire;          /* 目标接线 */
        wire_t          frame;         /* 参照系接线；0 = 世界系 */
        uint64_t        issued_at_ns;  /* 发出时刻（调用者时钟） */
        uint64_t        duration_ns;   /* 新鲜度窗口长度 */
        uint8_t         dof;           /* 有效分量数，≤ 6 */
        motion_fixed_t  motion[6];     /* 相对 frame 的速度，Q32.32 定点 */
} motion_event_t;
```

刻意**不存在**的东西：

```
命令码        MOVING / STILL 枚举      模式字段
目标位置与速度的区别（都是 motion 分量）
载荷 payload  优先级  回调
```

#### 从物件收到的全部内容

**什么都没有。** `base_arrive()` 不带参数：到达本身就是全部内容。

单位、控制周期等自述属性由物件自己保存，大脑经 `object_declared()` 直读，不经过基座（设计决定 17）。基座对一条接线只知道：它此刻是否活着。

因此物件在全系统里只有**两种存在形态**：**活着**（句柄有效且世代匹配）与**不存在**（死句柄）。二元，没有第三种。

#### 物件的状态在哪

在物件自己那里，基座连它存在都不知道：

```
position[3]   orientation[4]   motion[6]   frame   duration_ns   carry[3]   dof   event_count
```

### 3.7 为什么是「零个状态」

若基座要存「这个物件现在运动还是静止」，就必须同时持有**参照系**才能比较 —— 而参照系是**信息**。基座一旦存它，无状态即崩塌。

> 静止是一种相对的运动。**判定属于大脑，施加属于基座。**

所以「运动 / 静止」不是基座里的一个取值，而是 `motion[]` 相对 `frame` 是否为零 —— **每次现算，不存**。

### 3.8 「状态物件自报」报到哪里

物件确实自报状态，但**不报给基座**，而是**报给大脑**（直连，见 §7）。

参考实现是 `object_motion(wire, i)`：新大脑接上后直接读现场。这就是「物件即记忆」的接口，对应设计决定 8 与本体论第 3 条。

## 4. 上层大脑

- **可热插拔，无缝**
- 只与基座在**运动控制**这一件事上发生关系
- 负责**判定**：静止还是运动（因为需要参照系，而参照系是信息）
- 负责**意图与策略**：为什么动、该怎么动
- 其余一切：与物件**直连**

### 大脑也是普通接线

基座眼里**没有「大脑」这个类别**。大脑只是恰好「正在驱动基座」的那条接线：

- 大脑接入基座用 `base_arrive`，和任何物件无异 —— **没有「大脑槽」**
- 换大脑 = 让旧的大脑线 `depart`、新的大脑线 `arrive`，与物件热插拔是**同一个机制**
- 基座**对称**：不对任何一条线搞特殊，不设「只有大脑才能下令」的检查
- 大脑可以叠大脑，任意堆层；堆到哪层算顶，由开放系统运行时决定，不由基座规定
- **「会思考」与「会动」在基座里是同一种东西**：都是某条线上的 `motion` 向量。
  区别只在物件自己如何解释这些分量 —— 大脑把它解释为认知，手脚把它解释为位移。
  基座不解释

> **一切皆是运动物件；基座是唯一一个不是运动物件的东西。**
> 基座不是世界里的物，它是世界的运动控制函数。

### 大脑无缝靠什么

基座无状态，因此**大脑的现场不在基座**，而在**物件**。

新大脑接上后，直接向物件读取现场 —— 这之所以可行，正因为「物件直连大脑」。

> **大脑的无缝，靠的是物件即记忆。**

## 5. 物件

- 即插即用，热插拔
- 运动受基座控制
- 其他信息与大脑直连
- 自带运动能力（自己的驱动与闭环）
- **不定义对错**：它只被施加运动，并向上报告

---

## 6. 两种热插拔的异同

**相同点只有一条**：都是热插拔 —— 接入与离开都不需要停机。其余全部不同。

| | 物件热插拔 | 大脑热插拔 |
|---|---|---|
| 无缝的含义 | **身体不中断** | **意识不中断** |
| 谁保证 | 基座（识别并纳入控制） | 基座（持续运行） |
| 状态的所在 | 物件自己 | 物件（大脑去读） |
| 断了的后果 | 物理事故 | **目标**：变呆，不变危（当前尚无特权隔离，见下） |
| 技术难点 | 物理连续性 | 认知连续性（语言统一） |
| 定义正确？ | 否 | 是 |
| 换了什么 | 世界的肢体 | 世界的价值观 |

> **物件无缝是身体不中断，大脑无缝是意识不中断。**
> 前者靠物件的自主，后者靠物件的记忆。

> **现状校正（见 [assessment.md](assessment.md) §4.2）**：「变呆不变危」是**目标**，
> 不是当前事实。当前没有任何特权隔离 —— x86_64 页全部可写可执行且 `CR0.WP=0`，
> riscv64 处于 `satp=0` 的 Bare 模式。在一颗大脑与基座同权的情况下，出错的大脑
> 既能变呆，也能直接破坏基座。要让这句话成立，必须先有执行隔离。

## 7. 通道模型：运动是唯一窄腰

```
              上层大脑（可热插拔）
              ╱                    ╲
   运动控制（唯一通路，自描述）      其他一切信息（直连）
            ╱                          ╲
           ▼                            ▼
    ┌─────────────┐                 ┌────────┐
    │   基座       │   施加运动       │  物件   │
    │  无状态      ├────────────────▶│        │
    └─────────────┘                 └────────┘
```

就像 IP 是网络的窄腰 —— 所有应用都从它上面过，但应用之间通信不靠它。

| 通道 | 内容 | 是否经过基座 |
|---|---|---|
| 运动控制 | 自描述的运动事件 | **必须** |
| 其他一切 | 传感、意图、图像、数据 | **不经过** |

## 8. 已确认的设计决定

1. 基座自己就是一个大脑，只做运动控制这一件事
2. 基座**无状态**，不保存信息
3. 基座持有**接线**（管线），不持有**信息**（内容）
4. 基座是运动控制的**唯一通路**
5. 运动控制事件**自描述**（自带参照系与时长）
6. 唯一原语是**施加运动**；「静止」是参照系取自身运动的结果
7. 上层大脑可热插拔、无缝；只与基座在运动控制上发生关系
8. 其他一切信息：物件与大脑**直连**
9. 静止 / 运动的判定属于大脑，不属于基座
10. `duration_ns` 是命令的**新鲜度窗口**：事件自带发出时刻 `issued_at_ns`，只在 `[issued_at_ns, issued_at_ns + duration_ns]` 内**可被接受**，过期事件以 `MOTION_E_DEADLINE` 拒绝、绝不执行。**接受之后**，物件沿该事件持续运动 —— 拾取器模型的「自持」保留在窗口之后，窗口只约束「迟到多久还算数」
11. 运动控制事件是**定点、无载荷、自描述**的：`{wire, frame, issued_at_ns, duration_ns, dof, motion[]}`
12. `motion` 表示**相对 frame 的运动**；「静止」即 `motion = 0`
13. **一切皆是运动物件**；大脑也是普通接线，**没有「大脑槽」**。基座对称、不授权、不裁决；大脑可叠大脑、任意堆层。**基座是唯一的非物件** —— 它不是世界里的物，而是世界的运动控制函数
14. **接线句柄跨槽位复用保持稳定**：编码为 `(世代号 << 16) | 槽位`，世代号单调递增。离开的句柄永不复活 —— 否则热插拔之后，旧大脑会对着占用同一槽位的新物件下指令
15. **参照系由物件自己解（方案 A）**：物件沿参照链直读参照系物件的运动，**物件之间可以直连**，不经过基座。基座只校验 `frame` 这条线当下是否有效 —— 它看不见参照链，因此也发现不了环；成环与断链由物件侧发现并拒绝
16. **执行模型在基座之外**：执行层按每个物件到达时自述的 `period_ns` 推进它的运动环；时间由调用者（架构层时钟）给出，基座不调度、不计时。未申报周期（`period_ns = 0`）的物件不被推进；落后时不补跑，从当前时刻重新排期。四条时间纪律：**（a）时间只能前进** —— `now_ns` 小于上一次被接受的时刻即返回 `OBJECT_RUN_E_CLOCK_ROLLBACK`，且不推进任何物件；**（b）排期加法不许回绕** —— `now_ns + period_ns` 与 `next_due_ns + period_ns` 均经 checked 加法，回绕返回 `OBJECT_RUN_E_TIME_OVERFLOW`；**（c）两遍提交** —— 第一遍只计算排期、第二遍才写状态，任何失败都不会留下「半张表已推进」；**（d）首次只排期** —— 物件第一次被执行层看见时不积分，插上就多走一个周期等于把从未经过的时间算进位置。调用者手上的硬件节拍与执行层时间轴不是同一条，应经 `object_now_ns()` 取当前执行时刻再加自己实测的增量
17. **基座对接线只知道「是否活着」**：`base_arrive()` 不带参数，接线表每槽只有世代号与在用标记。单位、控制周期等自述属性由物件自己保存，大脑经 `object_declared()` 直读，不经过基座
18. **运动量纲冻结**：`motion[0..2]` 是线速度（m/s），`motion[3..5]` 是角速度（rad/s），全部 Q32.32。物件按自述的 `period_ns` 把速度积分到位姿：`position += v * period_ns`。积分用**余数进位**，不是每步各自取整 —— 否则舍入误差恒为同号，会随步数线性累积，等于让速度被周期改写。所有定点加、减、乘、旋转、参照链累加和位置累计必须经过 checked 算术层；越界必须显式失败，禁止依赖 C 有符号回绕。设备原生单位（度、编码器 tick、毫米）由物件适配层换算，不进入基座通道；因此「同一事件在不同周期的物件上产生相同的世界速度」是可验证的性质，而不是约定
19. **声明之外不进入模型**：`dof` 是命令的权威边界。事件只在 `motion[0..dof-1]` 上有分量，接受时把 `dof` 之外的分量归零；能力申报只在 `i < cap.dof` 的轴上有效，其余轴清零。理由是同一条：尾部往往是上一条命令的残值或未初始化的栈内容，而参照链按 6 轴累加，一个 `dof = 1` 的物件因此能把「没被命令的角速度」加进子物件的世界运动。**没被声明的东西不是数据，是噪声**，模型不该读它
20. **申报即承诺**：物件申报的能力会被校验，非法申报**整体拒绝**（`dof > 6`、有效轴上 `limit_min > limit_max`、`max_rate < 0`、`mass < 0`），且不留下半份记录；申报过的非零 `max_rate` 会在物件侧真正拦住超限命令（`MOTION_E_LIMIT`），幅值判定对 `INT64_MIN` 单独处理。**申报了却不执行，等于死字段** —— `duration_ns` 曾经就是这样一块装饰。行程上限（`limit_min/limit_max`）目前只做结构校验、尚未在积分处生效；它是作用在**实测位姿**上的约束，与「命令 / 解算 / 实测」三者的分离一起处理
21. **基座纯净性可被静态断言**：`base/base.c` 里不得出现 `cap`、`limit_min`、`limit_max`、`max_rate`、`mass`、`orientation`、`position`、`described`、`still` 这些名字，由 `make check-purity` 断言。基座一旦理解这些名字，它就开始理解世界，「无状态」也就随之失效 —— 这条不变量因此不是口号，而是一个会失败的门禁
22. **命令、解算、实测必须分离**：`cmd_motion` 是本物件相对 `frame` 的命令速度；`state.position`、`state.linear`、`state.angular` 是物件相对 `frame` 的实测/自持状态；`object_resolve()` 才给出世界视角。执行层只把本地命令积分进本地位姿，绝不把世界解算结果写回。完整刚体速度逐级按 `v' = Rv + v_F + ω_F × Rr`、`ω' = Rω + ω_F` 复合，位置耦合用实测相对位置；外部改写位姿时清空旧轨迹的积分余数。查询命名同样服从这条边界：`object_commanded_is_zero()` 只说明相对参照系的命令为零，不声称物件在世界中静止
23. **姿态必须真的是旋转**：非零 `orientation` 在 `object_set_state()` 入口按 `|q|² = 1 ± 1/1024` 校验，非法整份拒绝、一个字段都不写；全零表示「未申报姿态」，按无旋转处理。理由不是洁癖：用 `2q` 旋转会把向量放大两倍，而错误表现成「精度问题」，比直接报错危险得多。**「还没上报」不是「报了错的」**，两者必须分开
24. **解算失败必须有成因**：`object_resolve()` 返回 `object_resolve_status_t`，区分空指针、目标不存在、参照链断开、成环、链深度超限和 checked 算术溢出。成环与「合法但过长」是两种需要不同修复的现场，此前共用一个 `depth >= MAX` 判定，长链会被误报成环。注意 `OBJECT_RESOLVE_OK` 为 0：把返回值当真值用会让「成功」为假，调用者必须显式比较
25. **世代号耗尽 = 槽位退役，而不是回绕**：句柄把 32 位世代号放在位 16..47，只有 1..0xFFFFFFFF 可表示。再递增会回绕成 0、被强制改成 1 —— 于是「第一次使用」的句柄复活，指向陌生物件；1 kHz 热插拔下约 50 天就碰得到。修法不是加宽编码，而是**不再发号**：一个槽位无法再造出互不相同的句柄时，永久退役。退役是「哪个口还能用」的接线信息，不是世界信息
26. **接线可见时刻 = 状态就绪时刻**：`object_plug()` 先填好除接线外的一切字段，最后才写接线并置 `in_use` —— 接线是发布点。旧实现先发布接线再初始化，窗口内命令会被接受，却按**上一个占用者**的 frame、周期与速率上限判定；那不是「这只手没准备好」，而是「命令进了错误的参照系」。`object_unplug()` 则先置不可见再交还接线，顺序同样不能反
27. **模糊测试必须可证伪**：`tests/host/fuzz_base.c` 用固定种子施加随机的插拔、命令、姿态、申报、调度与解算序列，并由影子表独立对账。但「跑了多少轮零失败」本身不是证据 —— 证据是**把已知缺陷放回去，语料必须报错**。因此该语料对两个回退变异体做过实测：命令尾部不归零（数千次失败）、能力申报不校验（上千次失败）。同时必须写明它**抓不到什么**：`object_plug()` 的发布顺序窗口在单线程下是等价变异体（函数返回前状态已一致），只有并发读者才看得见，因此那条纪律由顺序论证与复用槽位测试保证，而不是由模糊测试冒充
28. **大脑热切换 = 事件来源的替换，没有交接物**：`brain/` 是基座之上的参考实现：一个大脑由一条普通接线、一个决策周期和一个只读「目标 + 现在」的决策函数组成。切换就是停掉旧大脑、装上新手脑；基座全程不知情，`base/base.c` 里连 `brain` 这个词都不许出现（`make check-purity` 已把它加入名单）。**更强的一条性质**：换大脑时不需要任何交接 —— 新大脑第一次决策读的是物件自持的实测状态（`cruise` 把物件推到 +1.99 m，`shuttle` 因此读到正值并反向推，1 秒后位置 1.49 m）。**诚实边界**：切换是协作式的，基座没有权限模型，拦不住旧大脑继续调用 `base_apply`；旧大脑的迟到事件之所以被拒，是因为它的新鲜度窗口已经关闭，不是因为基座认得出「这是旧大脑」。真正的隔离属于阶段 9/10 的监视与 MMU，仍未实现
29. **监视只能观察，判断不进基座**：`monitor/` 在基座之上读取 `base_wire_valid`、`object_state`、`object_capability` 与 `object_resolve`，并观察调用者传入的 `object_run_status_t`，产出事件（接线非预期消失、解算失败、实测与命令偏差、实测越界、执行层拒绝时刻）。`monitor_poll()` **不调用 `object_run`、不调用 `base_apply`、不写物件状态**；执行层必须由调用者单独推进，再把结果交给监视器。这条「观察者而非干预者」由目标侧自检与宿主边界测试共同证明：轮询前后物件状态、执行时钟和步数必须完全相同。速度越界判断直接比较 `rate > limit || rate < -limit`，不对实测值取绝对值，因此 `INT64_MIN` 也不会触发有符号溢出。**故障只报一次就注销** —— 世代号保证消失的接线不会复活，重复报同一起故障只会淹没后续现场。
30. **MMU 隔离 = 页表做 W^X 的尽力部分，不是义务论上的沙箱**：x86_64 的 2 MiB 大页与 riscv64 的 Sv39 4 KiB 页各自把能做的做到位，并把做不到的写进文档。x86_64 在当前页表下把 2 MiB 以上的 511 个大页设为非可执行（第 0 页含代码与数据同页，标了就会第一条指令缺页），并置位 `CR0.WP`；riscv64 用 4 KiB 页真正做到 .text R|X、.rodata R、数据/栈 R|W，并映射 UART/PCIe 的设备窗口。**决定 30 只写「现在有什么」**：没有 U 态、没有大脑沙箱、没有授权模型。任何把「打开 satp」写成「已经隔离」的文案都必须通过自检的 `mmu failures = 0` 标记来对账
